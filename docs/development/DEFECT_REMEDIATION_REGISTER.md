# OPHIREUM NETWORK (`OMPNETWORK`) — Defect Remediation Register (Phases 31–46)

**Release Candidate**: `ophireum-network@1.0.0-rc.1`  
**Verification Policy**: Every defect listed below was independently reproduced or identified during Phases 31–46 source inspection and verified fixed via automated tests, strict TypeScript/ESLint gates, PostgreSQL 16 PGlite execution, or compiled server smoke checks.

| Defect ID | Severity | Domain | Root Cause Identified | Concrete Source-Code Remediation | Verification Evidence |
|---|---|---|---|---|---|
| **DEF-31-01** | High | Backend Production Runtime | Production server started via `tsx` dev runner rather than a deterministic compiled ESM artifact; missing Railway build/healthcheck manifest. | Added permanent `dist/server/index.mjs` build target (`npm run build:server`), updated `package.json` `"start": "node dist/server/index.mjs"`, resolved static `dist` relative to compiled output in `server.ts`, and created `railway.json`. | `npm run build:all` + `npm run smoke:prod` |
| **DEF-31-02** | High | Resilience & Observability | No centralized circuit breakers, timeouts, exponential backoff retries, graceful draining state on `/api/ready`, or universal log secret redaction. | Created `src/server/resilience.ts` (`AppError`, `CircuitBreakerRegistry`, `withTimeout`, `retryWithJitter`, `createRuntimeLifecycleState`, `redactSensitiveText`), wired into `src/server/logger.ts`, `src/server/app.ts`, and `server.ts`. | `tests/enterprise-phases31-46.test.ts` + `scripts/prod-smoke-check.mjs` |
| **DEF-32-01** | High | AI Conversation Privacy & Memory | AI messages and memory lacked automatic sensitive-data redaction, consent-gated long-term memory, token-budgeted context assembly, and RA 10173 export bundle. | Created append-only `supabase/migrations/006_enterprise_reliability_and_ai_memory.sql`, wired `redactSensitiveText()` into `conversationService.ts`, implemented `recordConsent()`, consent-gated `saveMemory()`, `buildTokenBudgetedContext()`, and `POST /api/consultant/session/:id/consent` + `GET /api/consultant/session/:id/export`. | `tests/enterprise-phases31-46.test.ts` + `tests/postgres-migrations.test.ts` |
| **DEF-34-01** | **Critical** | Webhook Signature Integrity | Payment webhook (`portalRoutes.ts`) and Resend webhook (`app.ts`) contained `req.rawBody \|\| JSON.stringify(req.body \|\| {})` fallback, weakening cryptographic signature verification if raw bytes were absent. | Removed all `JSON.stringify(req.body)` fallbacks; endpoints fail closed with HTTP `400 RAW_BODY_REQUIRED` when exact `rawBody` is missing; added CI static check prohibiting regression. | `tests/enterprise-phases31-46.test.ts` + `.github/workflows/ci.yml` |
| **DEF-34-02** | High | Financial Governance & Replay Defense | Payment adapters lacked ±5-minute timestamp replay skew enforcement, unmatched webhook reconciliation queue, dispute register, and dual-control maker-checker segregation of duties. | Added `validateWebhookTimestampWindow()` in `paymentAdapters.ts`, created `src/server/portal/payments/financialGovernance.ts`, added DB tables + `chk_maker_checker_distinct_actors` constraint in Migration `006`, and exposed `/api/admin/payments/{reconciliation,maker-checker,disputes}` + refund threshold guard. | `tests/enterprise-phases31-46.test.ts` + `tests/postgres-migrations.test.ts` |
| **DEF-36-01** | High | Production RAG Safety | Knowledge ingestion did not scan/quarantine leaked credentials or payment cards, and search did not expose explicit `RetrievalMode` diagnostics. | Added `RetrievalMode` enum (`LIVE_SEMANTIC_RETRIEVAL`, `DEGRADED_KEYWORD_RETRIEVAL`, `LOCAL_DEVELOPMENT_FALLBACK`, `PROVIDER_UNAVAILABLE`), sensitive-content scanning with auto-quarantine, manual `POST /api/ai/knowledge/documents/:id/quarantine`, and `searchWithDiagnostics()`. | `tests/enterprise-phases31-46.test.ts` |
| **DEF-37-01** | Medium | AI Workforce Queue & DLQ | Workforce execution lacked canonical state enum (`WorkforceExecutionState`), multi-worker lease claiming, retry backoff scheduling, and dead-letter queue visibility. | Added `WorkforceExecutionState`, `ai_workforce_job_queue`, `ai_workforce_dead_letters`, `claim_ai_workforce_job()` (`FOR UPDATE SKIP LOCKED`, `SET search_path = public, pg_temp`) in Migration `006`, implemented `enqueueJob`/`claimNextJob`/`failOrRetryJob` in `workforceService.ts`, and exposed `GET/POST /api/ai/jobs`. | `tests/enterprise-phases31-46.test.ts` + `tests/postgres-migrations.test.ts` |
| **DEF-38-01** | Medium | Package Metadata & Lint Hygiene | `package.json` still used placeholder `react-example@0.0.0`, mixed build/test tools in runtime `dependencies`, and ESLint reported 34 warnings. | Renamed to `ophireum-network@1.0.0-rc.1`, locked `engines.node >=22 <23`, moved dev tools cleanly to `devDependencies`, regenerated `package-lock.json`, and resolved all 34 ESLint warnings across 15 files to achieve **0 errors, 0 warnings**. | `npm run lint` + `npm audit --omit=dev` |
| **DEF-41-01** | Medium | CI/CD Security Enforcement | `ci.yml` ran `npm audit --omit=dev --audit-level=high \|\| true` (non-blocking), lacked least-privilege `permissions: contents: read`, lacked compiled server smoke check and SBOM generation. | Removed `\|\| true` so high/critical runtime vulnerabilities fail CI; added least-privilege `permissions: contents: read`, `smoke:prod`, `sbom`, and multi-browser Playwright config (`chromium`, `firefox`, `webkit`, `tablet`, `mobile`). | `.github/workflows/ci.yml` + `.github/workflows/deploy-pages.yml` + `playwright.config.ts` |
