# OPHIREUM NETWORK (`OMPNETWORK`) — Security Remediation Register

| ID | Vulnerability / Gap Addressed | Remediation Implemented | File(s) | Verification |
|---|---|---|---|---|
| SEC-01 | Admin session tokens persisted in browser `sessionStorage` | Removed all `sessionStorage` token storage from `EnterpriseModal.tsx` and `AdminConsoleApp.tsx`; tokens held strictly in JS memory with `HttpOnly`, `SameSite=Lax` cookie (`opm_admin_session`) and `credentials: 'include'`. | `src/components/EnterpriseModal.tsx`, `src/admin/AdminConsoleApp.tsx`, `src/server/auth.ts` | `enterprise-remediation.test.ts` |
| SEC-02 | Missing server-side admin token revocation on logout & cross-replica | Added `jti` claims, PostgreSQL `revoked_session_tokens` sync (`revokeSessionTokenAsync`), and `POST /api/admin/auth/logout`. | `src/server/auth.ts`, `src/server/routes/adminRoutes.ts`, `004_reconciliation_hardening.sql` | `security-negative.test.ts` |
| SEC-03 | Weak admin principal binding & session fixation risk | `requireAdmin` verifies live DB `id`, `role`, `isActive`; admin re-login revokes prior session token to prevent session fixation. | `src/server/auth.ts`, `src/server/app.ts` | `security-negative.test.ts` |
| SEC-04 | Coarse 2-role admin authorization | Expanded RBAC to 9 least-privilege roles enforced via `requirePermission()`. | `src/server/auth.ts`, `src/server/routes/adminRoutes.ts`, `src/server/routes/aiRoutes.ts` | 9-role boundary test in `security-negative.test.ts` |
| SEC-05 | MFA secret encryption, rotation, replay & lockout | Implemented RFC 6238 TOTP (`otpauth`), versioned `enc:v2:<kid>` AES-256-GCM encryption + zero-downtime `MFA_ENCRYPTION_KEY_PREVIOUS` rotation (`POST /api/admin/auth/mfa/rotate-key`), 5-attempt lockout, single-use recovery codes, and replay rejection. | `src/server/auth.ts`, `src/server/routes/adminRoutes.ts`, `004`, `006` | `security-negative.test.ts` |
| SEC-06 | PostgREST `.or()` filter string interpolation risk | Replaced `.or(...)` interpolation in `findActiveAdminByEmail()` with separate UUID-validated `.eq()` and `.ilike()` queries. | `src/server/db/supabaseRepository.ts` | Static review + build |
| SEC-07 | Non-constant-time appointment token check & reschedule bypass | Switched management token comparison to `crypto.timingSafeEqual`, added rate limiting, and enforced weekday/non-past validation. | `src/server/app.ts` | `enterprise-remediation.test.ts` |
| SEC-08 | Unbounded in-memory rate limiter | Implemented distributed PostgreSQL rate limiter (`check_and_increment_rate_limit()` RPC) with bounded local fallback (`maxKeys = 5000`). | `src/server/rateLimiter.ts`, `004_reconciliation_hardening.sql` | `postgres-migrations.test.ts` + `security-negative.test.ts` |
| SEC-09 | Mutable security/audit logs | Added PostgreSQL `BEFORE UPDATE OR DELETE` append-only triggers (`prevent_audit_log_mutation()`) on `audit_logs`, `ai_session_events`, and `auth_security_events`. | `003`, `005`, `006` | Real PostgreSQL 16 (`postgres-migrations.test.ts`) |
| SEC-10 | AI prompt injection, cross-tenant RAG leakage & leaked secrets in KB | Enforced strict tenant scoping, `<untrusted_knowledge_context>` framing, automatic sensitive-data quarantine (`status = 'quarantined'`), manual quarantine route, and strict production `gemini-embedding-2` guard. | `src/server/ai/knowledgeService.ts`, `src/server/routes/aiRoutes.ts`, `006` | `enterprise-phases31-46.test.ts` + `ai-conversation-live-voice.test.ts` |
| SEC-11 | Unauthorized live payment activation | Enforced server-side `403` safety lock blocking `live_payments_enabled = true` via API; PayMongo & GoTyme remain `deferred_merchant_onboarding`. | `src/server/routes/adminRoutes.ts`, `src/server/portal/payments/paymentAdapters.ts` | `security-negative.test.ts` |
| SEC-12 | Unsafe `JSON.stringify(req.body)` webhook signature fallback & replay risk (Phase 34) | Removed all `JSON.stringify(req.body)` fallbacks on payment and Resend webhooks (`400 RAW_BODY_REQUIRED` if raw bytes missing), added ±5-minute timestamp replay window (`validateWebhookTimestampWindow`), and added CI static prohibition check. | `src/server/portal/portalRoutes.ts`, `src/server/app.ts`, `src/server/portal/payments/paymentAdapters.ts`, `.github/workflows/ci.yml` | `enterprise-phases31-46.test.ts` + CI gate |
| SEC-13 | Single-actor high-value financial approval risk (Phase 34) | Implemented dual-control maker-checker segregation of duties above `$500` / `₱25,000` enforced at API (`403`) AND PostgreSQL constraint (`chk_maker_checker_distinct_actors`), plus unmatched reconciliation queue & dispute register. | `src/server/portal/payments/financialGovernance.ts`, `src/server/routes/adminRoutes.ts`, `006_enterprise_reliability_and_ai_memory.sql` | `enterprise-phases31-46.test.ts` + `postgres-migrations.test.ts` |
| SEC-14 | Sensitive secrets persisted in AI conversations or structured logs (Phases 31 & 32) | Created `redactSensitiveText()` (Luhn card PANs, CVV, JWT, Bearer, API keys, PEM keys, passwords) wired into structured JSON logger, AI conversation persistence, and consent-gated memory. | `src/server/resilience.ts`, `src/server/logger.ts`, `src/server/ai/conversationService.ts` | `enterprise-phases31-46.test.ts` |
| SEC-15 | Production silent fallback to local storage | Hardened production boot to fail closed with non-zero exit when `NODE_ENV=production` lacks Supabase credentials. | `src/server/app.ts`, `scripts/prod-smoke-check.mjs` | `npm run smoke:prod` + `security-negative.test.ts` |
